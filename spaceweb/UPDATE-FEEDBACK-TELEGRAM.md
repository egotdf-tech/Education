# Отзывы, уведомления организатора и Telegram

## Что исправлено

В новой вкладке «Отзывы и вопросы» организатор видит отзывы со ВСЕХ курсов, включая личные. Есть фильтры по курсу, видимости, вопросам и поиск по имени/тексту. Ответить можно в общем списке или в отдельном окне отзыва. Несохранённый ответ не пропадает при обновлении интерфейса. Старые пути через карточку студента и занятие сохранены.

Новый/изменённый отзыв и сообщение студента создают уведомление организатору. Оно открывает конкретный отзыв, а не случайно выбранный курс. Студент по-прежнему получает только уведомления о своих ответах/проверках. Прежние отзывы уже видны в общей вкладке; чтобы добавить их в уведомления, есть отдельная кнопка с защитой от повторного добавления.

## Установка на существующий сайт

1. Сохраните свежую копию базы и файлов в панели SpaceWeb — появились реальные ответы студентов, копия от предыдущего дня может их не содержать.
2. Распакуйте feedback-telegram-update.zip НА КОМПЬЮТЕРЕ.
3. В существующую ПРИВАТНУЮ bridge-app, рядом с public_html, добавьте feedback.php, telegram.php и замените notify.php. Остальные служебные файлы/папку storage не трогайте.
4. В public_html замените index.html, app.js, api.php, style.css и добавьте inbox.js. Подтверждайте замену, а не вторую копию файла. Папки assets/uploads, .htaccess и приватный bridge-config.php не заменяются.
5. Откройте сайт через HTTPS, обновите Ctrl+Shift+R. Войдите как организатор. Проверьте «Отзывы и вопросы → Все курсы» и нужный отзыв.
6. В «Уведомлениях» нажмите «Добавить уведомления о прежних отзывах», если хотите видеть и старые записи. Повторное нажатие не создаёт копий. Награды не выдаются повторно, отзывы не редактируются.

Схема базы не меняется, install.php и повторная установка НЕ требуются. Ключи, пароли, резервные копии, пользовательские картинки и данные в этот пакет не входят.

## Telegram: сначала бот

В Telegram откройте официальный https://t.me/BotFather, выполните /newbot, задайте название и свободный username, заканчивающийся на bot. Лучше отдельный бот только для БРИДЖ. BotFather выдаст токен — это пароль бота. Не отправляйте его разработчику в чат, не размещайте на GitHub и не вставляйте в адресную строку с URL Bot API.

Через файловый менеджер SpaceWeb откройте ПРИВАТНЫЙ bridge-config.php на уровень выше public_html. В существующий параметр telegram_token вставьте токен между одинарными кавычками. Другие настройки и пароли не меняйте. telegram_chat_id можно оставить пустым: получим его через подтверждение личного чата. После сохранения не присылайте скриншот файла с ключами.

## Подключение чата в кабинете

1. Войдите организатором → «Уведомления → Уведомления в Telegram».
2. «Проверить статус» подтверждает наличие токена/привязки в локальных настройках, а не доставку через Telegram.
3. Нажмите «Подключить личный чат», подтвердите пароль ОРГАНИЗАТОРА.
4. Откройте предложенную ссылку бота в СВОЁМ Telegram и нажмите Start / Запустить. Ссылка содержит одноразовый случайный код, действует 10 минут — не передавайте её другим.
5. Вернитесь на сайт и нажмите «Я нажал Start — проверить подключение». Принимается только личный чат с совпадающим кодом. Привязка сохраняется в приватной bridge-app/storage/telegram-binding.json, токен в браузер не возвращается.
6. Нажмите «Отправить тестовое сообщение». Убедитесь, что оно пришло именно вам. Если нет — пришлите текст ошибки, не токен.

Чужой бот с активным webhook автоматически НЕ переподключается: создайте отдельного бота. Запрещено отключать TLS-проверку ради подключения. Если хостинг не разрешает HTTPS-запросы к api.telegram.org или отключён allow_url_fopen, нужна настройка поддерживаемого исходящего доступа.

## Регулярная доставка

Привязка и тест ещё не включают фоновую доставку. Нужен планировщик SpaceWeb (cron) каждые 5 минут. Команда запускает PHP 8.4 CLI и приватный файл notify.php. Точный путь к файлу показывается организатору после проверки статуса; путь к PHP берётся из панели/документации SpaceWeb — не подставляйте случайный старый /usr/bin/php.

Обработчик НЕ открывается через браузер и не требует публичной ссылки с ключом. Он берёт токен и чат из приватных настроек. Старые уведомления уже стоят в очереди: после запуска возможна доставка сообщений за прошлые отзывы. Повторное добавление старых отзывов в Уведомления сайта не ставит их повторно в очередь Telegram.

Отправляются имя, занятие, тип события, видимость и ссылка на конкретный отзыв. Содержимое личного отзыва и домашнее задание в Telegram не копируются. По ссылке потребуется вход организатора.

При временном сбое сообщения остаются в очереди и повторяются позже. Сам факт сохранения отзыва не зависит от доступности Telegram. Нельзя гарантировать строго однократную доставку при потере ответа сети после принятия Telegram; штатный повторный запуск уже успешно обработанные записи не отправляет. «Проверить статус» показывает количество ожидающих сообщений. Период 5 минут — задержка доставки после настройки расписания, а не мгновенный push.

После настройки планировщика отправьте отзыв из тестового аккаунта, дождитесь сообщения и откройте ссылку. Реальные сообщения, токен и ID чата не публикуйте в отладочных логах/скриншотах.

## Проверки

На отдельной PHP 8.4/MySQL 8.4: уведомления для новых/изменённых личных отзывов и сообщений, адресное прочтение, добавление прежних отзывов без дубликатов и без новых наград, изоляция студента, отсутствие токена в ответах API. Telegram проверен на локальном имитаторе: пароль организатора, одноразовая связка с личным чатом, защита существующего webhook, тест, повторные попытки worker и отсутствие приватных текстов в сообщениях. Браузер: фильтры, поиск, ответы без потери черновика, открытие нужного отзыва и переход после входа, мобильные размеры. Настоящую связь SpaceWeb → Telegram проверяет владелец на шаге настройки; разработчик пока не получал доступа к хостингу/боту.
