# БРИДЖ: рабочая версия для SpaceWeb

## Что это

Отдельная серверная версия PHP 8.4 + MySQL 8.4, без фреймворка и сборки. Сохраняет выбранный стиль прототипа. Исходный прототип в корне репозитория остаётся неизменным. Сами файлы на SpaceWeb не отправляются при скачивании или публикации этой ветки.

Проверено локально на PHP 8.4/MySQL 8.4: установка таблиц, одноразовые коды, серверные права, приватность, сроки, блокировка проверенного ДЗ, отзывы, ответы, очередь Telegram, награды, создание курсов/занятий, XLSX и мобильная вёрстка. Настоящая отправка почты, Telegram, права файлов и восстановление копий на SpaceWeb требуют отдельной проверки. Тесты не отправляют настоящих писем и сообщений.

## Размещение файлов

```
папка аккаунта SpaceWeb/
├── bridge-config.php       ← ваш существующий файл с паролем базы
├── bridge-app/             ← загрузить сюда из пакета, ВНЕ public_html
│   ├── bootstrap.php
│   ├── schema.sql
│   ├── notify.php
│   └── config.example.php
└── public_html/            ← сюда СОДЕРЖИМОЕ public_html из пакета
    ├── index.html
    ├── style.css
    ├── app.js
    ├── api.php
    ├── install.php
    ├── assets/
    └── uploads/.htaccess
```

**Не загружайте bridge-config.php или bridge-app в публичную папку, GitHub или чат**. В публичном архиве только пример конфигурации. Настоящий пароль уже сохранён вами на SpaceWeb, в пакет он не входит.

## Порядок установки

1. Сделайте резервную копию существующих файлов public_html и базы через панель SpaceWeb. Сохраните текущую .htaccess отдельно. Не удаляйте cgi-bin или служебные файлы аккаунта.
2. В приватном `bridge-config.php` сохраните текущие host, port (3308), database, username и password. По примеру `bridge-app/config.example.php` добавьте:
   - `base_url`: `https://study.brigecorp.ru`
   - `admin_email`: адрес почты единственного организатора, к которому у вас есть доступ
   - `mail_from`: подтверждённый адрес отправителя, который разрешено использовать на SpaceWeb
   - `app_secret` и `setup_key`: два разных случайных секрета не короче 32 символов, сгенерированных менеджером паролей
   - поля Telegram пока можно оставить пустыми
3. Не включайте `environment=test` на хостинге. Это внутренний режим автоматических тестов: в нём код записывается в отдельный тестовый файл и cookie не требует HTTPS.
4. Загрузите bridge-app рядом с public_html. Затем загрузите содержимое public_html из пакета внутрь существующей public_html. Если редактор/архиватор скрывает .htaccess, включите показ скрытых файлов.
5. Существующее HTTPS-перенаправление уже проверено. Не затирайте его новыми непроверенными правилами: сравните файл из пакета и сохраните действующее правило. Из дополнений нужны запрет списка файлов и защита uploads от исполнения скриптов. Не меняйте настройки основного домена и почты.
6. Откройте **https://study.brigecorp.ru/install.php**. Введите `setup_key`, НЕ пароль базы. Ключ передаётся в POST по HTTPS, не в адресной строке. Установщик создаёт только таблицы с префиксом bridge_, без DROP, и учётную запись организатора.
7. После успешной установки удалите `install.php` из public_html. Также удалите старый `bridge-check.php`, если он остался. Приватный bridge-config.php сохраните.
8. Откройте сайт, введите имя и **admin_email**, получите код на почту. Проверьте папку спам. Если письмо не приходит, остановитесь на этом шаге: не показывайте код на сайте и не включайте тестовый режим. Нужно проверить отправителя и доставку почты на SpaceWeb.
9. Создайте один тестовый курс, код группы и несколько занятий. Используйте пока вымышленных участников и ответы.
10. Проверьте вход второго пользователя с другой почты: он не должен видеть управление и чужие личные ответы. Проверьте отметку во время занятия, закрытие после него, отзыв в 48 часов, ДЗ, проверку, уведомления и Excel.

Код входа действует 10 минут, может быть использован один раз, не хранится в базе открытым текстом. Неудачные попытки и частота запросов ограничены. Почта организатора назначается при установке; изменение admin_email в конфигурации не отзывает роль уже существующего администратора автоматически — для смены владельца нужен отдельный контролируемый шаг.

## Почта

В этой версии используется стандартная PHP mail() с текстовыми письмами. Требуется разрешённый отправитель и рабочая доставка на хостинге. Успешный вызов mail() означает передачу письма почтовой системе, а не гарантированное попадание в ящик. Нужно проверить реальные ящики, SPF/DKIM согласно настройкам провайдера и ограничения рассылки. При необходимости заменяется только функция доставки на SMTP, остальная авторизация сохраняется. Нельзя использовать тестовую запись кодов в файл для обхода проблем доставки в рабочей системе.

## Telegram

После входа и проверки кабинета отдельно создайте бота и приватный чат организатора. Токен и chat_id добавьте только в bridge-config.php. Worker отправляет имя, занятие, тип события и ссылку; текст личных отзывов и ДЗ в Telegram не копируется.

В планировщике SpaceWeb настройте CLI-вызов `bridge-app/notify.php` каждые 5 минут. Точный путь PHP CLI уточняется по панели/документации хостинга: не подставляйте случайный бинарник старой версии. Это не публичная ссылка. PHP должен иметь доступ к HTTPS и api.telegram.org с проверкой сертификатов.

При сбое сообщения остаются в очереди с повторными попытками; параллельные worker-процессы блокируются. Ненастроенный Telegram не мешает сохранению ответов. По умолчанию публичность отзыва не меняет выдачу наград. Старые отправленные записи очереди и временные данные авторизации очищаются при работе обработчика.

## Работа с курсами

Организатор создаёт курсы/занятия, меняет коды, преподавателей, изображения и задания на сайте. На старте каждая группа соответствует одному курсу и одному коду; код проверяется сервером, должность/стаж автоматически не проверяются. Назначенные преподаватели не получают аккаунты и права. В этой версии нет удаления курсов/студентов через интерфейс: ошибочные занятия можно отменить. Удаление персональных данных выполняется отдельно контролируемым администратором с учётом обязательств по хранению.

Уведомления внутри кабинета обновляются при действиях/обновлении страницы и раз в минуту, если не открыта форма. Письма об ответах не отправляются. Активную открытую форму автоматическое обновление не перезаписывает. Все ограничения сроков перепроверяются сервером при отправке.

## Обновления и резервные копии

Код и данные разделены: обновляя приложение, не перезаписывайте bridge-config.php, bridge-app/storage и public_html/uploads. Храните копии базы и загруженных изображений отдельно от основного сайта. Перед запуском согласуйте расписание резервирования и выполните тестовое восстановление на отдельной базе. Установщик не заменяет механизм миграций для будущих изменений схемы.

После изменения кода сначала тестируем на отдельной копии, затем обновляем основные файлы. Не переносите БД с реальными студентами в публичный GitHub или тесты. Для пробной версии используйте вымышленные данные, пока не проверены документы оператора, доступы, почта, резервирование и обслуживание.

## Тесты разработчика

Тесты запускаются только на одноразовой локальной базе с конфигурацией environment=test и приватным test_mailbox. `tests/integration.py` требует чистую установленную среду без предыдущего install.lock, `tests/browser.cjs` — данные первого теста. Для повторного полного запуска создавайте новую временную базу и отдельное хранилище. Контейнеры и тестовая почта не включаются в установочный архив.
